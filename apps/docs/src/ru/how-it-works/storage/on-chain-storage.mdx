## Что такое On-chain Storage

On-chain Storage хранит файл прямо внутри вашей персональной канистры, а не во внешнем storage-сервисе.

Это даёт более простую модель доверия, но и стоит дороже, потому что сам Internet Computer должен держать файл в памяти канистры.

:::note{title="О шифровании"}

On-chain Storage описывает, где хранится файл.  
Будет ли он зашифрован до загрузки, зависит от ваших настроек шифрования.

:::

## Где находится файл

![Архитектура On-chain Storage](/diagrams/fossflow-diagram-4.png)

Эта диаграмма показывает более простой путь On-chain Storage:

- браузер загружает файл напрямую в канистру
- персональная канистра хранит **файлы, метаданные, правила доступа и интерфейс приложения**
- здесь **нет внешнего gateway** и **нет внешнего object storage слоя**

В модели Rabbithole канистра может содержать не только сам файл и правила доступа, но и интерфейс приложения, через который вы к нему обращаетесь.

## Как работает загрузка

<Steps>

### Подготовка файла в браузере

Файл делится на части. Если шифрование включено, они шифруются локально до загрузки.

### Отправка частей файла в канистру

Браузер загружает части файла напрямую в вашу персональную канистру.

### Сохранение файла в вашей канистре

Канистра сохраняет файл вместе с записью о файле, правилами доступа и связанными данными проверки.

</Steps>

## Как работает скачивание

<Steps>

### Запрос частей файла у канистры

Браузер запрашивает у канистры данные файла.

### Проверка и локальное открытие

Браузер проверяет целостность и расшифровывает файл на вашем устройстве, если шифрование включено.

</Steps>

## Почему это дороже

- Каждый сохранённый байт живёт внутри памяти канистры.
- Сеть должна поддерживать это хранение во времени.
- Большие файлы становятся значительно дороже, чем в Blob Storage.

## Практические ограничения

On-chain Storage обычно лучше подходит, когда:

- файлы относительно небольшие
- файлов немного
- простота архитектуры важнее, чем экономия

Обычно это худший выбор для больших медиабиблиотек или дешёвого массового хранения.

## Почему модель доверия проще

При On-chain Storage нет внешнего file gateway и нет внешнего object storage слоя, который держит файл.

Поэтому путь хранения проще:

- браузер подготавливает файл
- канистра хранит файл
- браузер проверяет его и открывает

## Когда этот режим особенно полезен

On-chain Storage подходит лучше, если:

- вам нужна максимально простая архитектура
- суверенность важнее стоимости
- файлы относительно небольшие или их немного

## Практическое правило

Выбирайте **On-chain Storage** для небольших, но ценных файлов, где минимизация внешних зависимостей важнее стоимости.

Например:

- личные документы
- контракты и подписанные PDF
- резервные копии важных записей

Для больших архивов, медиаколлекций и экономичного хранения обычно лучше подходит **Blob Storage**.
